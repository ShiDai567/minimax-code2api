# 安全说明与能力边界

## 凭证与访问控制

- 账号上游凭证使用 Fernet 对称加密后写入数据库；API Key 仅保存 SHA-256 摘要，管理 Token 通过摘要比较验证。
- 账号列表只返回脱敏凭证；API Key 明文只在创建响应中返回一次。创建响应应在可信终端立即保存，不要写入日志或截图。
- 请求日志仅保留经筛选的请求头，并对授权、API Key 和 Cookie 类敏感字段脱敏；不要扩展为记录原始凭证或完整请求体。
- `ADMIN_TOKEN` 当前是单一管理凭证，不提供用户、角色、审计审批或细粒度权限隔离。`ApiKey.permissions` 当前不会形成完整的权限执行策略。
- 不要将服务直接暴露到公网。管理端应限制网络来源，并通过 TLS 反向代理保护传输。

## 上游账号

MiniMax Code 桌面端参考网关使用本地 auth-lease broker 获取 token；本服务没有实现该 broker。账号凭证由部署者提供，签到还需要 `real_user_id`。只录入拥有明确授权的凭证，并在可信环境中验证它们。

签到依赖官方 CLI 源码中观察到的签名和端点行为。它们不是稳定公开 API，可能在没有兼容性保证的情况下变化。国内与国际账号、分组及路由区域必须保持分离。

当前账号创建后的健康状态为 `unknown`。后端没有健康验证端点，也没有自动激活流程；网关只选择 `health=healthy` 的账号。因此新建账号不会自动承载请求。不要仅为了让账号进入路由池而手工设置 healthy，除非已在同一区域通过可信流程验证凭证与 Anthropic 上游请求。

## 业务数据可信度

- `source: "live"` 代表本地后端数据库数据，并非每个字段都来自实时上游确认。
- 签到奖励按上游报告存储，等待余额核对；签到成功不能推断奖励已到账。
- 余额同步是 Token Plan remains 快照，不应当视为 MiniMax Code 的通用余额或 API 实际消费。
- 当前不生成可靠的 API 实际扣款流水；网关日志中消耗字段可能为空。
- 未提供已验证的 `/v1/models` 模型清单；禁止通过硬编码模型、能力或价格来伪造动态发现结果。

## 未完成能力

- OpenAI Chat Completions 与 Responses 的请求/响应转换及 SSE 事件转换。
- 上游模型发现和模型能力/价格元数据。
- 账号认证/健康检查、凭证 broker、安全的账号激活流程。
- 定时及批量签到、批量进度记录、并发防护完善。
- 完整筛选/排序/分页、多选交互和逐条请求详情。
- 前端各导航页接入后端 adapter；当前不能把现有 mock 页面称为已完成联调。
- 生产级用户身份、RBAC、审计事件、CORS 策略、速率限制、密钥轮换及运维部署模板。

在上述能力实现前，界面或集成文档应明确显示 unknown、mock、unsupported 或待验证状态，不应将其表达为成功或真实业务事实。
